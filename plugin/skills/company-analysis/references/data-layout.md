# 리서치 워크스페이스 레이아웃

> 스킬이 프로젝트 폴더에서 실행될 때 생성하는 모든 파일의 위치·이름 규칙이다.

## 두 가지 원칙

**1) 계층 — 사실과 판단을 섞지 않는다**

| 계층 | 내용 | 해석 |
|---|---|---|
| `자료/` | 수집한 그대로의 raw | 금지 |
| `트래킹/` | 여러 자료에서 뽑아 시간순 정렬한 사실 | 금지 (→ `references/tracking.md`) |
| `계산/` | 스크립트 입출력 (assumptions·valuation) | — |
| `분석/` | 판단이 담긴 완성 리포트 | 여기서만 |

**2) 이름 — 수집일이 아니라 "내용이 덮는 기간"으로 짓는다**

DART 데이터는 불변 기록이다. FY2025 재무제표는 언제 받아도 FY2025다. 수집일을 파일명에
쓰면 같은 내용이 날짜만 바뀌어 중복되고, 정작 "이 데이터가 언제를 덮는지"는 알 수 없다.
그래서 **수집일은 frontmatter에, 파일명은 내용의 정체성으로** 간다.

| 성격 | 이름 규칙 | 예 |
|---|---|---|
| 확정 기간 데이터 (불변) | 사업연도·보고서 기간 | `재무제표-2025.md`, `사업보고서-2025.12-<접수번호>/` |
| 누적 시계열 (계속 확장) | 날짜 없이, 갱신하며 frontmatter에 `커버기간` | `재무추이.md`, `공시목록.md` |
| 수집 시점이 본질 | 기간 버킷 | `뉴스/2026-07.md` |
| 콘텐츠 자체에 시점이 있음 | 콘텐츠의 날짜 | `유튜브/2026-05-08-1분기-실적발표.md` (업로드일) |
| **판단** | **분석 일자** (판단은 시점이 곧 정체성) | `분석/2026-07-24-기본분석.md` |

시세(주가·시총)는 계속 변해 raw 로 쌓지 않는다 — 계산 시점 스냅샷이 기준일과 함께
`계산/*-assumptions.json` 에 남으므로 그것으로 충분하다.

## 기업

```
리서치/기업/<종목명>/
├── manifest.json                   # 수집·분석 이력의 단일 상태 파일 (아래 별도 절)
├── 자료/                           # raw — 수집한 그대로, 해석 없이
│   ├── 재무/재무추이.md                 # 4년+분기 매출·이익률·ROE·부채·현금흐름·FCF (갱신)
│   ├── 재무/재무제표-<사업연도>.md       # BS·IS·CIS·CF·SCE 전 계정 덤프 (원 단위, 확정 후 불변)
│   ├── 재무/재무지표.md                 # 공식 수익성·안정성·성장성·활동성
│   ├── 공시/공시목록.md                 # 공시 목록 + 유증·CB 플래그 (갱신)
│   ├── 공시/주요사항.md                 # 유증·CB·BW·자사주·소송 상세
│   ├── 공시/지분거래.md                 # 대량보유·임원 소유보고
│   ├── 공시/지배구조-<사업연도>.md       # 최대주주·배당·직원·타법인출자
│   ├── 원본/<보고서종류>-<기간>-<접수번호>/  # 정기보고서 원본 + 목차별 md
│   │   ├── INDEX.md                     #   섹션 목록(주석 ★·사업의내용 ☆) + 독해 체크리스트
│   │   ├── <접수번호>.xml               #   원본 그대로 — 수치 인용 시 대조 기준
│   │   └── NN-<섹션제목>.md             #   목차 단위 (하위 목차는 ## 헤딩)
│   ├── IR/<기간>-<제목>.md              # IR 자료·가이던스·컨콜 발췌
│   ├── 뉴스/<YYYY-MM>.md                # 월 버킷 — 목록 + 선별 기사 발췌
│   └── 유튜브/<업로드일>-<제목>.md       # 자막 전사 (URL·타임스탬프)
├── 트래킹/                         # 사실 시계열 — 규칙은 references/tracking.md
│   ├── 자금조달-지분희석.md
│   ├── 캐파-투자집행.md
│   └── <주제>.md                        # 해당 사항 있는 주제만, 자유 추가
├── 계산/                           # 스크립트 입출력 — 재계산 가능해야 한다
│   ├── YYYY-MM-DD-assumptions.json      # valuation.py 입력 (가정 + 시세 스냅샷·기준일)
│   └── YYYY-MM-DD-valuation.json        # valuation.py 출력 (9칸·낙점·진입가)
└── 분석/                           # 판단 — 날짜가 정체성
    ├── YYYY-MM-DD-기본분석.md
    └── YYYY-MM-DD-심층분석.md
```

## manifest.json — 기업별 상태 파일

`dart.py` 등 수집 스크립트가 자동으로 쓰고, 분석 시작 시 에이전트가 읽는다.

```json
{
  "종목": "크래프톤", "티커": "259960", "corp_code": "00760971",
  "시장": "KOSPI", "결산월": "12",
  "수집": {
    "재무":     {"커버": "2022~2026 1Q", "연도별접수번호": {"2024": "...", "2025": "..."},
                "최종수집": "2026-07-24"},
    "공시목록": {"커버": "2026-01-25~2026-07-24", "최종접수번호": "20260721001347",
                "건수": 90, "최종수집": "..."},
    "사업보고서": {"보고서": "[기재정정]사업보고서 (2025.12)", "기간": "2025.12",
                 "접수번호": "...", "섹션수": 14, "최종수집": "..."}
  },
  "정정이력": [
    {"감지일": "...", "대상": "재무제표 2024", "이전접수번호": "...", "새접수번호": "...",
     "메모": "기재정정 — 해당 연도 수치가 바뀌었을 수 있다"}
  ],
  "분석": [{"일자": "2026-07-24", "모드": "기본", "낙점적정주가": 370884,
           "상승여력": 52.9, "진입가": 123628, "안전마진충족": false, "파일": "분석/..."}],
  "트래킹": [{"주제": "자사주 매입과 소각", "파일": "트래킹/...", "최종갱신": "..."}]
}
```

용도 넷:

1. **증분 수집** — `공시목록.최종접수번호` 이후만 가져오면 된다 (트래커의 전제).
2. **정정 감지** — `재무.연도별접수번호`가 바뀌면 그 사업연도가 기재정정된 것이다.
   어느 해가 정정됐는지까지 특정되며, `정정이력`에 자동 기록되고 재무추이 md에도 경고가 붙는다.
   **정정은 그 자체로 경계 신호**이므로 리포트에 반드시 언급한다.
3. **추정의 갱신** — 과거 분석의 적정주가·진입가·판정을 갖고 있어, 과거 리포트를 다 읽지
   않고도 "무엇이 왜 달라졌는가"를 쓸 수 있다.
4. **재수집 판단** — 파일 mtime이 아니라 명시적 커버기간으로 판정한다.

## 산업

```
리서치/산업/<산업명>/
├── 자료/
│   ├── 시장규모/    # 침투율·수요 통계 (금액 기준)
│   ├── 점유율/      # 기업·국가별 점유율 로데이터 (분해 전 원본)
│   ├── 정책/        # 규제·보조금·관세 원문 발췌
│   ├── 뉴스/<YYYY-MM>.md
│   └── 유튜브/<업로드일>-<제목>.md
├── 트래킹/          # 산업 사실 시계열 (정책 변화, 침투율 추이, 캐파 증설 경쟁 등)
├── 계산/
│   └── 채점표-<YYYY-MM>.md   # 경쟁력 축·기업별 상중하·서열
└── 분석/
    └── YYYY-MM-DD-산업분석.md
```

산업도 `manifest.json` 을 같은 방식으로 쓴다(수집 이력·분석 이력·트래킹 목록).

## raw 자료 파일 규칙

모든 `자료/` 파일은 맨 위에 최소 frontmatter를 단다 — 나중에 이 숫자를 다시 쓸 때
"언제, 어디서 가져온 값인가"가 파일 자체에 남아야 한다.

```yaml
---
수집일: YYYY-MM-DD        # 언제 가져왔나
출처: <URL 또는 문서명>
커버기간: <이 데이터가 덮는 기간>   # 해당하면
---
```

- **파일명에 수집일을 쓰지 않는다.** 위 "이름" 원칙표를 따른다.
- raw 파일에는 해석·판단을 쓰지 않는다. 숫자·표·발췌만. 해석은 리포트에서.
- 같은 대상을 다시 수집하면 새 파일을 만들지 말고 **같은 파일을 갱신**한다.
  (DART 데이터는 불변이므로 보통 내용이 같고, 다르면 정정이라 manifest가 잡아낸다.)
- 유튜브 파일은 frontmatter 출처에 영상 URL을 적고, 인용 발췌마다 타임스탬프를 단다
  (예: `[12:34]`) — 나중에 원 발언을 재확인할 수 있어야 한다.

## 스킬 실행 시 동작 규칙

1. **분석 시작 시**: `manifest.json` 을 먼저 읽는다 — 무엇을 어디까지 수집했는지,
   과거 분석의 판정이 무엇이었는지, 트래킹 문서가 무엇이 있는지가 여기 다 있다.
   커버기간이 최신(재무·공시·IR 90일 이내)이면 재수집을 건너뛴다. 시세(주가·시총)만은
   매번 새로 확인한다(저장은 assumptions.json 에).
2. **수집하면서 저장한다**: 웹에서 가져온 원데이터는 리포트에 넣기 전에 `자료/` 하위에
   먼저 기록한다. 리포트의 모든 표는 `자료/` 파일에서 나와야 한다. 스크립트가 수집한
   항목은 manifest에 자동 기록된다.
3. **정정이 감지되면 반드시 다룬다**: manifest의 `정정이력`에 이번 런에서 추가된 항목이
   있으면, 해당 사업연도 수치가 바뀌었다는 뜻이다. 리포트에 언급하고, 사유가 회계 오류
   수정이면 경계 신호로 취급한다. 트래킹 문서에도 한 줄로 남긴다.
4. **트래킹 문서를 확인·갱신한다**: `트래킹/` 의 각 문서 최종갱신일을 보고, 이번 수집분에
   새 사실이 있으면 줄을 추가한다. 심층 분석 중 새 주제를 발견하면 문서를 만든다.
   규칙은 `references/tracking.md`.
5. **계산은 `계산/` 을 거친다**: assumptions.json 을 쓰고 → valuation.py 실행 →
   valuation.json 저장 → 리포트에는 스크립트가 출력한 표를 붙인다.
6. **리포트는 `분석/` 에 저장하고**, 저장 전 validate_report.py 게이트를 통과해야 한다
   (통과할 때까지 수정). 저장 후 manifest의 `분석` 이력에 판정(낙점적정주가·진입가·
   안전마진충족)을 추가한다.
7. 폴더가 없으면 만든다. 종목 루트에는 manifest.json 과 자료/·트래킹/·계산/·분석/ 외의
   파일을 두지 않는다.
