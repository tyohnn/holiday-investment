# 감독 · 서브에이전트 운영

산업지도는 메인이 감독·의사결정권자·QC이고, 실행은 서브에이전트가 한다.
2026-08-06 기업분석 런과 2026-08-27 산업지도 런에서 확정.

## 역할

| 역할 | 하는 일 | 하지 않는 일 |
|---|---|---|
| 메인(감독) | 5장 설계, 유니버스 확정, 잠금 매출, 프롬프트 작성, 숫자 전달 전 sanity, **QC**, 종합 | 장 본문을 직접 조사·집필 |
| 서브(sonnet) | 맡은 장 또는 주석 한계표를 끝까지 수행 | 자기 하위 에이전트, 다른 장 범위 침범 |

트리를 **2단**으로 유지한다. 3단이 되면 이름 해석이 깨진다(`general-purpose`는
타입명이라 형제 회신이 튕긴다). 하위가 형제의 정상 메시지를 프롬프트 인젝션으로
거부한 사례가 있다. 분해가 필요하면 감독에게 올린다.

## 프롬프트에 넣을 것 (빠지면 재작성)

1. 읽을 레퍼런스 **절대경로** (`schema-traps.md`, `notes-protocol.md`,
   `chapter-template.md`의 해당 장, `query-recipes.md`)
2. 원격 Supabase 조회 레시피 (자격은 env에서 읽으라고만 — 키를 프롬프트에 붙여 넣지 않음)
3. 스키마 함정
4. 산출 경로와 필수 절
5. 감독 잠금표 (매출·주석 한계). 웹에서 받아 전달한 값은 원문 대조 여부를 표기
6. "모르면 `확인 불가`. 지어내지 마라. 하위를 띄우지 마라."

교재 경로를 넣지 않는다.

## 산출은 파일, 회신은 요약

긴 본문을 채팅으로 반환시키지 않는다. 응답이 길면 스트림이 끊긴다.
`리서치/산업/<산업>/분석/<날짜>-<주제>.md`에 Write하고 **20줄 이내 요약만** 반환.
한 번의 Write가 크면 뼈대를 먼저 쓰고 Edit으로 섹션을 채운다.

## 죽은 에이전트

처음부터 다시 하지 않는다. 트랜스크립트가 있으면 재개하고, 그동안 다른 에이전트가
확보한 사실을 같이 넘긴다. 하위가 죽어 감독이 대기 중이면
"기다리지 말고 확인 불가로 쓰고 마무리하라"고 지시한다.

## 웹 한도와 시세

- WebSearch 세션 한도가 있다. 소진되면 WebFetch만 남긴다.
- 주가·시총: `https://finance.daum.net/quotes/A<종목코드>`.
- 시장 전체가 급등·급락한 날의 개별 등락을 종목 고유 재료로 읽지 않는다. 날짜를 먼저 확인.

## 감독이 넘기는 값도 QC 대상

한 에이전트의 웹 숫자를 원자료 확인 없이 다른 에이전트에 전달하면 오염이 전파된다.
전달 전:

1. 자릿수 — 분기 > 연간, 한 회사가 산업 전체보다 큼.
2. 모수 — 대수 vs 금액, 신차 침투 vs 보유 대수, 전사 vs 부문.
3. 단위 — 억/조/백만 원, 톤/GWh, ×1000 NOTE.
4. 원문 — 유료 원문을 못 열면 재인용 등급을 명시하고, 같은 기사를 인용하고도
   본문에 `확인 불가`로 남긴 숫자(2026-08-27 삼성SDI 비중국 점유)는 QC가 원문을 다시 연다.

## QC를 생략하지 않는다

서브에이전트가 적은 "~는 목록에 없다", "인접 분류", "확인 불가"는 결함 신호다.
표본이 잘린 채 순위표를 만든 산출물은 재실행한다. 체크리스트는 `qc-gates.md`.
